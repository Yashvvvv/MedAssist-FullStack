# Deploying MedAssist (free tier)

**Render** runs the Docker image. **Supabase** provides PostgreSQL and file storage. Both have free tiers that don't expire. Total cost: ₹0. Expect about 30 minutes the first time.

> Render's free web services sleep after 15 minutes without traffic. The next request wakes the service in about a minute, which is fine for a demo and a resume link. For real pharmacies, use a paid instance (no sleep) or any always-on host.

## 1. Supabase: database and storage

1. Create a project at <https://supabase.com> (region: **Mumbai, ap-south-1**). Save the database password somewhere safe.
2. **Database URL:** Project → **Connect** → **Session pooler**. It looks like
   `postgresql://postgres.<ref>:<password>@aws-0-ap-south-1.pooler.supabase.com:5432/postgres`.
   Turn it into the three values the app reads:
   - `DATABASE_URL` = `jdbc:postgresql://aws-0-ap-south-1.pooler.supabase.com:5432/postgres?sslmode=require`
   - `DATABASE_USERNAME` = `postgres.<ref>`
   - `DATABASE_PASSWORD` = your database password

   Use the **session** pooler (port 5432), not the transaction pooler (6543). Flyway migrations and JDBC prepared statements need a real session.
3. **Storage:** Storage → **New bucket** → name `medassist`, **private** (prescriptions are medical data). Then Project Settings → **API**: copy the Project URL (`SUPABASE_URL`) and the `service_role` key (`SUPABASE_SERVICE_KEY`). The service key bypasses all security rules, so it goes only into Render, never into the app or the repo.

Flyway creates every table on the first start. You don't run any SQL by hand.

## 2. Render: the API

1. Push this repo to GitHub.
2. At <https://render.com>: **New → Blueprint**, pick the repo. Render reads `render.yaml` and proposes the `medassist-api` service.
3. Fill in the values marked "sync: false":

   | Key | Value |
   |---|---|
   | `DATABASE_URL`, `DATABASE_USERNAME`, `DATABASE_PASSWORD` | from step 1.2 |
   | `SUPABASE_URL`, `SUPABASE_SERVICE_KEY` | from step 1.3 |
   | `PUBLIC_BASE_URL` | `https://medassist-api.onrender.com` (your service URL; used in email links) |
   | `GEMINI_API_KEY` | from <https://aistudio.google.com/apikey> (optional: the AI endpoints return `503` without it) |

   `JWT_SECRET` is generated by Render. `DEMO_DATA=true` seeds the demo pharmacy.
4. **Apply.** The first build takes a few minutes. When it finishes, check:
   - `https://<service>.onrender.com/actuator/health` returns `{"status":"UP"}`
   - `https://<service>.onrender.com/swagger-ui.html` opens, and logging in as `demo@medassist.app` / `Demo@12345` works

## 3. Optional providers

| Feature | Variables | Without it |
|---|---|---|
| Email (verification, reset, invites) | `MAIL_HOST`, `MAIL_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD`, `MAIL_FROM` (e.g. Brevo or Resend SMTP, both free) | emails are written to the log |
| Razorpay subscriptions | `BILLING_PROVIDER=razorpay`, `RAZORPAY_WEBHOOK_SECRET`, `RAZORPAY_PLAN_PRO`, `RAZORPAY_PLAN_BUSINESS`; webhook URL `https://<service>/api/v1/billing/webhooks/razorpay` with events `subscription.*` | owners switch plans in-app (manual billing) |

## 4. Before real pharmacy data

The demo setup is for showing the product. Before a real pharmacy uses it:

- [ ] Set `DEMO_DATA=false`. The demo logins are public, so delete the demo organization or use a fresh database.
- [ ] Use a paid, always-on instance, so scheduled jobs (refill reminders at 09:00) run on time.
- [ ] Turn on Supabase's daily backups (Pro plan) or schedule a `pg_dump`.
- [ ] Configure email, so password reset works.
- [ ] Set `CORS_ALLOWED_ORIGINS` to the real web dashboard origin, if there is one.
- [ ] Get a privacy policy and terms reviewed. The app stores prescriptions, which are sensitive personal data under India's DPDP Act 2023.

## Running the image anywhere else

```bash
docker build -t medassist-api backend
docker run -p 8080:8080 \
  -e DATABASE_URL=jdbc:postgresql://<host>:5432/<db> -e DATABASE_USERNAME=... -e DATABASE_PASSWORD=... \
  -e JWT_SECRET="$(openssl rand -base64 48)" \
  medassist-api
```

The image runs as a non-root user, defaults to the `prod` profile, sizes the heap to 75% of the container's memory, and exposes Actuator health probes at `/actuator/health/liveness` and `/actuator/health/readiness`.
